# Roadmap

The **agent-facing iteration interface** for `maid` — helping an agent (or a developer working manually) iterate on a codebase, make wise decisions, use fewer tokens, and operate within a strict set of constraints. Every capability is available identically from the CLI and the MCP server.

## Done

1. **Guided project initialization (CLI and MCP)** — `maid init` and `maid mcp` share one guide that captures goal, scope/non-goals, software/stack (with repository detection), design principles, constraints, and best practices. The MCP server advertises the flow through server `instructions`, the `initialize-project` prompt, and the `project_init` tool; the CLI prompts directly for the same required fields. Best-practice defaults — including small atomic git commits, format/check before commit, and testing expectations — are applied without prompting. Callers request the optional settings catalog only when desired (`include: "optional"` or `maid init --show-options`). `project_update` and `maid init` persist the result to `maid.project.json`, optionally merge tooling overrides into `maid.config.json`, and deterministically regenerate `PROJECT.md` from both configs (never model-generated). `project_read` exposes the saved context and can verify that `PROJECT.md` is in sync. Because MCP is pull-based, the caller decides which questions to present.
2. **Status and iteration interface (CLI and MCP)** — `maid status` / MCP `status` return one compact payload covering project context, pending/HEAD/history snapshots, working-tree state, benchmark, score, dependencies, and commit readiness. All insight surfaces share `src/insights/` core functions and support deterministic `json` plus token-efficient `toon` output.
3. **Benchmarking of scores** — `maid benchmark` / MCP `benchmark` compare the current snapshot against a configurable baseline (default: previous commit) and explicit targets for test pass rate, FTA, cyclomatic complexity, Halstead bugs, and LOC. Per-test fixed/broken/added/removed outcomes and recent trends are included.
4. **Composite commit score** — `maid score` / MCP `score` combine gate outcomes, FTA, complexity, tests, benchmark trend, and dependency impact into a transparent 0-100 score with configurable weights and grade cutoffs. Every component reports its normalized value, weight, and contribution.
5. **Dependency/library selection guidance** — `maid dependencies` / MCP `dependencies` compare dependency manifests against the baseline, apply configurable penalties/bonuses per scope, honor `allow`/`deny` lists, and award offsets for measurable LOC/complexity reductions. `package.json` is supported behind an extensible manifest adapter.
6. **Commit guidance** — `maid commit-guide` / MCP `commit_guide` (plus the `commit-guidance` prompt) check pending snapshots, tests, gate outcomes, commit size, and dependency separation. They return blockers, warnings, split suggestions, and a suggested conventional commit message so commits stay small and iterative.

## Status

All roadmap items are **implemented** in both the CLI and MCP. The insight core lives in `src/insights/`; CLI commands and MCP tools are thin adapters over it. Configuration lives under the top-level `insights` key in `maid.config.json`. Documentation: [Insights](./insights.md), [MCP and codegraph](./mcp-and-codegraph.md), [Configuration](./configuration.md#insights).

Current implemented foundations include the CLI, Biome-first/functional formatting constraints, FTA metrics/gates, SQLite snapshots in `./maid.db` with per-test results, pending-as-`current` reporting, tracked hooks, the MCP tools (`metrics`, `gate`, `history`, `codegraph`, `status`, `benchmark`, `score`, `dependencies`, `commit_guide`), and project initialization (`maid init`, `project_init`, `project_update`, `project_read`, plus deterministic `PROJECT.md` generation).
