# MCP and codegraph

MAID can run as an [MCP](https://modelcontextprotocol.io/) stdio server so AI agents can query metrics and project analysis tools.

## Start the server

```bash
bun src/cli/index.ts mcp
```

(Also `bun run mcp`.) The server uses stdio transport (`src/mcp/server.ts`).

## Tools

| Tool | Description |
|---|---|
| `project_init` | Start guided project initialization. Returns required questions, repository-detected software, automatic defaults, and optionally the optional settings catalog (`include: "required" \| "optional" \| "all"`). |
| `project_update` | Merge validated project context and optional `maid.config.json` overrides; writes `maid.project.json` and deterministically regenerates `PROJECT.md`. Supports `dryRun`. |
| `project_read` | Read the saved project context as Markdown (default) or JSON, and optionally verify that `PROJECT.md` is in sync. |
| `metrics` | Run FTA on a path and return results (`json`/`toon`/`table`). |
| `gate` | Check FTA results against configured thresholds; reports pass/fail and violations. |
| `history` | Read aggregated snapshot history from `./maid.db` (tests, LOC, gate counts, cyclo, FTA, Halstead; includes pending as `current` where supported). |
| `codegraph` | Inspect code-graph index status or run code-graph commands/queries (supports `query` or exact `args`). Requires an index (e.g. `bunx @sdsrs/code-graph incremental-index`). |

Tool availability/behavior is implemented in `src/mcp/server.ts` and respects project config where applicable.

## Project initialization

MCP is pull-based: the server cannot spontaneously ask the user questions. Instead it advertises setup through the server `instructions` returned at initialization, the `project_init` tool, and an optional `initialize-project` prompt. The calling agent decides which questions to present.

1. **Inspect** — call `project_init` with the default `include: "required"`. It returns:
   - `status`: `missing`, `partial`, or `complete`
   - `missing`: unresolved required fields
   - `detected`: name, goal hint, and software detected from `package.json`, lockfiles, `tsconfig.json`, `biome.json`, and similar manifests
   - `required`: questions the caller may ask
   - `defaults`: values that are applied automatically and should not be prompted for (including best-practice git commits, formatting, and testing expectations)
2. **Optional only if desired** — call `project_init` with `include: "optional"` (or `"all"`) to get the optional settings catalog. This includes design notes, constraints, best-practice overrides, and tooling settings such as formatting, metrics thresholds, and MCP toggles. Use it only when the user asks to review options.
3. **Save** — call `project_update` with a `project` object and, when selected, a `config` object. `dryRun: true` validates and renders without writing.

`maid.project.json` is canonical. `PROJECT.md` is a deterministic projection of `maid.project.json` plus the effective `maid.config.json`; it is generated by code and must not be hand-edited. `project_read({ verify: true })` reports whether the generated document is in sync.

## Codegraph setup

MAID integrates with `@sdsrs/code-graph`. Typical setup (see also `cli.sh init`):

```bash
bunx -y @sdsrs/code-graph incremental-index
```

Model/index paths may depend on environment variables (e.g. `CODE_GRAPH_MODEL_DIR`, `CODE_GRAPH_HOOK_INDEX`). The MCP `codegraph` tool reports when no index is found and can execute supported commands when configured.

## Configuration

`maid.config.json` includes an `mcp` section (e.g. `codegraph`, `metrics` toggles) used by the application’s MCP/config logic.
